1. What we're building

A web app that pulls a student's classes and assignments from Canvas (and from syllabus text), lets them fix anything, plans weekly study time per class, and syncs everything to Google Calendar or Outlook with reminders. A short AI summary says what matters today and this week. Free, built for the BYU-Idaho hackathon.

  • Everything is editable. Items, dates, class names, class times, study times.
  • Study time is per class. The student sets weekly study times for each class (no shared study time). Each block shows what that class has due, and the student stars the assignments they'll work on in that block.
  • The synced calendar explains itself. Study events say what to study for in their notes; emoji in titles tell study, class, and due date apart.
  • Nothing is silently lost. Deletes go to Recently deleted for 1 day; study time changes need Confirm.

Out of scope: payments, native apps, drag-and-drop on the calendar (removed in the prototype on purpose), lecture recording, group features.

2. Rules for Claude

  1. Match the prototype. Copy, layout, states, and behavior come from it.
  2. One source of truth for types: frontend/src/types/ (TypeScript) mirrored by backend/app/schemas.py (Pydantic). Change both together.
  3. Components never call fetch or Supabase directly. Components use hooks; hooks use src/services/.
  4. Validate at every boundary: zod in the browser, Pydantic in FastAPI.
  5. Secrets live only in the backend. Nothing secret gets a VITE_ prefix.
  6. Pure logic (study-block expansion, show filter, sync event building) lives in src/lib/ or backend/app/ pure functions with tests.
  7. TypeScript strict, no any. Small files (about 150 lines max for components).
  8. Every async action has loading, empty, and error states.
  9. Don't add libraries beyond the stack list without asking Yujin.
  10. Work one phase at a time and run the checks in section 14 before moving on.

5. Data model

Tables are in supabase/migrations/001_init.sql. Every table has row-level security: a user only sees their own rows.

TableHolds
coursescode, name (editable), color, credits, hours per week (credits × 2.5), online (yes / no / unanswered), in-person meetings [{day, start, end}], confirmed
itemstitle, type (assignment, quiz, exam, project, reading, other), due date and time, status (todo / done), source, confidence, soft-delete time, Google event id
study_timesper class: weekday, start, end (weekly, repeating)
block_links"studying for": one study block occurrence (date|start) linked to an item
reminder_rulesminutes-before offsets per item type
connectionsencrypted Canvas token or feed URL, encrypted Google refresh token, Google calendar id. Backend only.
ai_usagedaily AI call count per user. Backend only.

An item is done if the student marked it done, otherwise if its due date is before today. A link to a done item stops showing (it comes back if the item is marked not done).

6. Backend API

All routes need Authorization: Bearer <Supabase access token>.

RouteDoes
GET /api/healthConfig check (no secrets returned)
GET /api/meWho is signed in, which connections exist
POST /api/canvas/connectSave a Canvas access token (checked against Canvas first) or a calendar feed URL, encrypted
POST /api/canvas/importPull active courses and assignments (token) or feed events (URL) into courses and items
POST /api/syllabus/parseGemini reads syllabus text (Canvas syllabus page or pasted PDF text) and returns class times, credits, and items with confidence
POST /api/{google|outlook}/startReturns the consent page URL with a signed 10-minute state
GET /api/{google|outlook}/callbackExchanges the code, stores the refresh token encrypted, sends the browser back to Reminders and sync
POST /api/{google|outlook}/syncCreate or update events in a separate "Syllabus Planner" calendar; removes upcoming events that no longer exist
POST /api/{google|outlook}/remove-all, /disconnectDelete the app's calendar; forget the connection
POST /api/summaryGemini summary for today or this week from item titles and dates only; daily limit per user

7. Screens and features (from the prototype)

Sidebar

Fixed to the window height; it does not stretch or scroll with the page. Buttons: Add classes, Review items, Study time, Calendar, Reminders and sync, Recently deleted, and the background picker (Original, Sky clouds) at the bottom. Hover labels.

Add classes

Connect Canvas (access token first, calendar feed URL as fallback) or upload syllabus PDFs. Each uploaded syllabus can be deleted (asks first, goes to Recently deleted). All text on the Canvas card is high-contrast: white, bold, smaller sizes only.

Review items

Class tabs; editable table; class names editable; flagged rows for unclear items; delete asks first and goes to Recently deleted. Class times panel: in person (sessions with different times on different days) or online (then a "Set up study time" button). Confirm asks "Confirm CSE 280?" and then opens Study time for that class. A class's meeting times only appear on the calendar after it is confirmed.

Study time

Class tabs only (no shared study time). Per weekday rows with time windows; Add time; quick setups Mornings, Afternoons, Evenings, Clear (active one filled). Changes are drafts: each class has its own Confirm / Discard bar (Confirm asks "Confirm CSE 325 study time?" and stays on the page), tabs show "Unsaved", "Confirm all classes" appears when several changed, and leaving with unsaved changes asks Confirm and leave / Discard / Keep editing. Undo after confirming.

Calendar

  • Day, Week, Month views; Ctrl/Cmd + scroll zooms; month navigation.
  • Filter bar: All classes plus one button per class. Show menu: To do (default), Everything, Done, No assignments, plus a Study time switch. Shows "+N hidden".
  • Due items appear at their due time with an alarm icon. Study blocks are filled in the class color with a book icon. In-person classes are outlined in the class color with a school icon. Key below the calendar.
  • Clicking a study block opens its card: "Studying for in this block" (starred items, removable), due on that day ("Nothing due today" when empty), and a week list with back/forward showing only days with something due. Check items done without closing. "Edit CSE 325 study time" jumps to that class's study time.
  • Side panel: compact expandable AI summary (Today / Week), then Overview (Day / Week / Month range; title, then done bar, then overdue count, which hide while expanded).
  • Item card: details, edit, mark done, delete (asks first).

Reminders and sync

Reminders by type; connect Google Calendar (Outlook later); Sync preview showing today and tomorrow exactly as the synced events will look; "Emoji in event titles" switch; AI summary schedule.

Recently deleted

Deleted items stay 1 day with Restore and Delete now (with undo).

8. Planning logic

  • Hours per week per class = credits × 2.5 by default (BYU-Idaho guideline: 2 to 3 hours per credit), editable. The study page compares set-aside time with this.
  • Study blocks are weekly per class: {courseId, weekday, start, end}. Occurrences are generated for each date; a block's key is YYYY-MM-DD|start.
  • A block's card lists that class's items due on that day and the selected week.
  • Show filter: To do = not done; Everything; Done; No assignments; study time on or off. Class buttons pick which classes.

9. Calendar sync format

Due date⏰ Due: W08 Teaching Truth postat the due timeClass, type, reminders from the user's rules
Done item✅ Done: W08 Teaching Truth postat the due timeKept as a record; reminders removed

Events go into a separate "Syllabus Planner" Google calendar (scope calendar.app.created). Every event carries a hidden tag (syllabusPlanner=1) and its own key, so:

  • Re-sync updates events in place: done items turn into ✅, edited study blocks and starred assignments update their notes, deleted items and removed study times disappear (upcoming events only; past ones are left alone).
  • Remove everything deletes the Syllabus Planner calendar in one step. The student's own events are never touched.
  • Sync is one-way (app → calendar). The app is where students plan and check things off; their normal calendar is where they see it.
  • Sync uses the free Google Calendar API, no AI. Run it on demand from Reminders and sync, and automatically a few seconds after a change.

10. Security (demo level)

  • Secrets only in backend env vars (Vercel settings); .env is git-ignored.
  • Every API route checks the Supabase access token; every table has row-level security.
  • Canvas tokens, feed URLs, and Google refresh tokens are encrypted (Fernet) and never sent back to the browser.
  • Canvas URLs must be HTTPS on instructure.com (blocks the server being used to fetch other sites).
  • AI calls are limited per user per day; inputs are size-capped; only titles and dates go to Gemini (free tier may use inputs to improve Google's products).
  • Syllabus HTML is sanitized before display. CORS allows only the app's own origins. Security headers set in vercel.json.
  • Google app stays in Testing mode with listed test users for the demo.

11. Errors and edge cases

  • BYU-I blocks student Canvas tokens → offer the calendar feed URL.
  • Canvas assignment with no due date → listed in Review as "No date", not synced.
  • Due date with no time → 11:59 PM.
  • Class with no meeting times → flagged in Review until marked online or given times.
  • Google token revoked → sync returns "Reconnect Google" and nothing is lost.
  • Sync partly fails → report counts; re-running doesn't duplicate.
  • AI daily limit reached → clear message; the app works without AI.

12. Design guidelines

Copy the prototype's tokens (dark theme, opaque gray cards, class colors c1–c3, warning colors), shapes (18 px cards, pill buttons), and animations (card-in, expand with clip, reduced motion respected). Class colors always come with an icon or label, never color alone. Plain sentence-case copy.

13. Phases

Phase 1: Foundation ✅

Repo, Vercel Services config, Supabase schema with RLS, FastAPI with every integration route.

Phase 2: App shell and Review ✅

Start screen (Canvas token or Try the demo), sidebar, tokens, backgrounds, Review screen with editable items, rename, class times, Recently deleted.

Phase 3: Calendar ✅

Month / Week / Day, Show menu, zoom, key, item card, study block card with starring, Overview, AI summary card. Overlapping study blocks sit side by side.

Phase 4: Study time ✅

Per-class weekly times, quick setups, drafts with Confirm, leave guard.

Phase 5: Reminders and sync ✅

Reminder rules, Sync preview, emoji switch, Google Calendar and Outlook connect, send, and remove.

Phase 6: Polish and stretch

Test with real keys, mobile pass, installable on phones (PWA), demo script. Not ported from the prototype: scheduled AI summaries (daily / week ahead), which need a scheduler.

After the hackathon

Native mobile app (checking things off and reminders on the go), two-way sync, more schools' Canvas.
